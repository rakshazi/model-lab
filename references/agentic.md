# Agentic skills: scripts, checkers, gates, loops

Measured on a 27B security audit (260 and 420 tool calls, deterministic verifier) and on a 4B writing an AGENTS.md (30 to 300 tool calls, a fact ledger, an audit script, twelve variants). The rule comes first, then the run that taught it.

## Scripts over prose

- **Automate whatever has one right answer.** Tool discovery, boilerplate, citations, counts: a deterministic script costs the model nothing, and every line of prose about it costs attention. Give the model world knowledge as the exact command (`govulncheck ./...`), never as a `--help` dump. It will read `--help` itself when it needs it. The interface an agent expects from a bundled script: `references/skill-format.md`, "Scripts" (read when the script ships with the skill).
- **Write the checker before the prompt, and run it on your own example first.** The discovery-doc audit (every cited ID defined, every forcing column filled, placeholders, example leaks) found four defects in the hand-written example on its first run.
- **Keep the shape check cheap and blind, and run semantics separately.** A gate once proved every cited line exists, every heading is present and every count matches while the content was wrong.
- **Let the checker accept legitimate content.** A placeholder check rejected an inline HTML payload in a stored-XSS finding, and the model spent two rounds rewriting the report to satisfy it. A checker that fires on valid output teaches the model to fight the checker. The same class recurred with angle brackets in inline code (`CASE WHEN <cond> THEN -id`, `wc -c < file`): three of eight FAIL lines were the checker, so it now strips inline code before scanning for placeholders, and keeps a test for each look-alike.
- **Print the enclosing symbol of every citation.** A plain existence check passes a citation to the wrong function. One line per citation (`path:range -> func PayOrder | item title`) exposed five mismatches, including two items that cited each other's sink. Name the statement that performs the effect: a line next to the real one in the same function passed both checks twice.
- **Make the citation check fail, and let its hint print by default.** One audit run made 13 of 31 citations to a neighbouring function and 5 to a bare path, and its gate passed every one: it proved the path exists and the line is in range, which is all a shape check can do, while the symbol hint that would have shown `func BatchOrders | P1 Delete order` sat behind a `--citations` flag the model never passed. A bare path with no line is a hard fail now, and the symbol line prints on every run.
- **The checker must accept the shape the rule and the template produce.** One audit gate parsed a citation only between backticks while the rule said `Sink: path:line` and the run wrote exactly that: 28 of 32 gate failures were that regex, and the four real miscites stayed behind them until a hand audit. Run the checker on output generated from the skill's own template, and keep a test for the bare form next to the quoted one.
- **A checker fits the inputs it was written on, the way a prompt fits the model it was tuned on.** Before it gates a run, run it over outputs it has never seen (every draft in the lab, every arm and model, the no-skill baseline too) and read each hit. A check with one right answer (an ID is defined, a file exists) may hard-fail. A check that encodes a judgment (this sentence presents an open question as settled) is a heuristic: fail only its unambiguous form and let the rest warn. A discovery audit's open-question check, on its first pass over nine drafts it was never written on, flagged `Resolve Q-01`, cells holding only IDs and "might need", and missed a leak behind a resolved row whose answer read `Pending`. The lab's own graders are scripts too: an assertion that wanted `BR-0[0-9]` failed two of three correct drafts that wrote `BR-1`, and moved the arm from 0.98 to 0.75 on paper.
- **A copyable command must obey the rule under it.** The proof reference said "keep both overlay paths relative to the repo" directly under a `printf` that interpolated the class directory as an absolute path. Twenty-five control classes copied the command, every control build failed once the run directory moved to the review host, and the rerun reported 31 of 31 controls as `ctrl=2`. When a paragraph constrains an artifact, the snippet above it has to already satisfy the constraint; the model copies the snippet.
- **A script's arguments arrive in the shape the model thinks in.** A look-first script took key words as separate arguments; a 26B MoE passed them as one quoted phrase in 6 of 6 calls (`"tables blog posts"`), and the fixed-string match found nothing. Split and normalise inside the script (whitespace, case, plurals); a documented calling convention loses to the phrase.
- **Give the table ids and check coverage.** A 39-row scan table and a 40-row lead ledger never referenced each other, and all 12 misses sat in rows already scanned. An id column plus "every row is named by a lead" turns the table into a checklist. Cover every table that can hold a defect: a state sweep without a lead column recorded "stale copy never invalidated" in a cell and no lead ever cited it, while the covered entry-point table lost nothing.
- **One id per row is not coverage.** After the sweep gained a lead column, the cache row cited the lead for the tenant-key bug and passed the row check while "no lock on the map" and "stale forever" sat in the same row with no lead: both were keyed findings the run missed. Check each cell that can hold a defect (repeat, concurrent); a check on the row misses them.

## Gates and the loop surface

- **Run the gate mid-flight, in small batches.** Twenty-eight artifacts written before any of them ran: half failed, and five controls passed on the vulnerable build. In batches of 5 to 7 with the gate after each, every failure got repaired next to its cause, and the run finished its proofs 4h21m in, where the previous one spent two of its four hours on repairs.
- **Filter the mid-run gate to the new batch.** One audit gate re-ran every PoC after each 3 to 5 new ones, then the final check re-ran all of them: a 30-PoC run paid roughly 3x the executions. Pass the new slugs to the gate and keep the full suite for one final pass.
- **Gate the proof sparingly.** A per-artifact proof tax (PoC, control, block, rerun) spends the budget on the artifacts already found. One audit skill wrote a block per PoC with a control for every item: 0/26 miscitations, but 2x the wall time of a one-shot report at 6.3% and similar recall (70.4% vs 67.4%), a 3-point coverage edge against a probe-first baseline when the user's metric was missed bugs. For a report that is a lead list, an exact citation on P0/P1 and a probe-backed row on P2/P3 is enough, and the fix session re-checks the low-severity rows anyway. Prove P0/P1 and the findings whose fix depends on the proof; leave P2/P3 as probe-backed leads under `Not proven`, and run the full proof suite once.
- **Grade the deliverable and skip the paperwork.** Two skill versions on the same five-target stand: the bare prompt took 2h04m and 141 calls for 25.6 of 38 entries; the structured skill took 5h13m and 355 calls for 30.6. The +5 entries were almost all tier 2, and tier 3/4 sat at the baseline. The extra 3h went to artifacts nothing graded: a recon table, a lead ledger, a sink sweep with a probe per cell, a scanner ledger, a coverage section, and per-finding block files assembled into the report. Two of every five turns maintained state. Keep the graded output (the report and its PoCs) and make everything else a one-line scratch list; the checklist that raises the hard tiers belongs in the body, applied in a sweep when the candidate list runs dry, where it costs a couple of turns.

- **Name the control classes and say which fits which claim.** "Run it with CONTROL=1" got five tautological controls, since a smaller attack cannot prove a check is missing. Naming patched-copy, benign-input and feature-absent, and requiring the patch for a missing check, made the model build one. When the claim is "the check is absent", write the patch first, so both halves of the proof come from one motion.
- **Guard the sides of a gate.** Every gate that checked only the output got passed by changing something else: a 4B shrank its file to a 27-`sed` stub to clear a copy check, added fake targets to the repo's Makefile to clear "target has no rule", and deleted its own ledger to clear "ledger missing". A fail on any modified tracked file closed that route.
- **Gates in series move the failure.** Fake exit codes, then stub files, then repo edits, then stuffing, then loops: each gate pushed the failure to the next cheapest way out, and none improved the draft. After three in a row, subtract back to the last variant that drafted well and keep only the guards that prevent damage. A reverse check ("every ledger command must appear in the file") made the 4B dump 40 commands onto one line.
- **A rule read once at hour 1 does not bind at hour 5.** All seven misses of a 4h15m audit were already lines in the skill's own reference (a deny-list role gate, double-encoded traversal, CSV formula in an export cell, CSRF on a cookie-authenticated write, time-seeded tokens, static-salt hashes, TLS verification off, stale cache); the reference was read once at minute 18 and the PoCs were written hours 1 to 4 across two compactions. On omp the first user message is re-sent verbatim after a rollover, while a reference read is a tool result and may not survive, which is why the body rule binds at hour 5 and the reference rule fades. Put the check where the decision happens: a table cell the gate reads, a file the model copies, a generator it fills. Keep prose for the why. Another audit shows the same shape: it missed four state and output entries its reference named; the reference was read once before the compaction and the proof pass came later. What a given harness re-sends after a rollover: `references/agents/omp.md`, "What the model receives" (read when a rule vanished mid-run on omp).
- **A checklist needs a loop that names each item, and that loop needs a command.** One audit skill's body carried twelve checks and the model answered each one once (the cache key, one role gate, the CSV cell, the order-creation CSRF), while the lock, the invalidation, the stats role gate, the invoice template and the email CSRF stayed unfound in the same proved files: all 11 misses sat in a file with a green PoC. Naming the siblings fixed four of them in the next version; the run after that swept exactly those four named pairs and missed the fifth cookie-authenticated write (the email change) while its own notes counted check 12 as answered by the order-creation POST. Give the sweep a command that prints every row (`sed -n '/Routes/,/^}/p' <router>`) and the check id each row answers, so the scope is the code under audit and any list of examples stays a hint. Run it from the batch step instead of behind "when the list runs dry".
- **A harness failure exits with the code the checker reads as success.** Two audit runs moved to a new path, their `go build` of the patched copy failed under `set -e`, the control exited 1, and the gate read 76 controls as "the attack was blocked" until the overlays were rewritten. A control that dies and a control that blocks share an exit code; require the absence line (`ABSENT: <check>`) on stdout and reserve exit 2 for a dead build, then fail a control that exits 1 without it.
- **A generated artifact belongs to its generator.** A run deleted a refuted PoC with `rm`, the generator recreated it on its next call, and the directory shipped as a refuted proof with no block. Another regenerated nine PoCs after their last gate and shipped one that no longer reproduces its finding. Record the script hash at gate time, fail a script changed since its last gate, and delete slugs in the generator.
- **One record covering several defects passes every coverage check.** Four of five audits wrote a single cache lead for an unkeyed read, an unsynchronized map and a missing invalidation; the sweep's `Concurrent` cell answered with the key lead, the gate accepted the id, and the lock was never mentioned in 1.4 MB of thinking. Require a distinct id per defect cell and fail a cell that shares its id with another.
- **A proof that cannot fail is worse than a missing one.** One cache PoC printed the stale flag and exited 0 either way; one race PoC retried five times over ten objects and passed twice. Both shipped as findings because the gate reads exit codes. Assert the flag inside the exit, and put a probabilistic burst under `Not proven` with its margin.
- **A hint the checker prints is a rule read at the wrong time.** Sixteen `REOPEN?` lines across five audits named a blocked lead that shared a file with a proven one, and none was answered; one run printed `CITE ... func ResetConfirm | P1 PATCH /v1/users/me` twice and closed with it on screen. The model reads the line and still needs the fact. Print the sibling's reproduced line under the hint, and count the unanswered ones. Another audit printed a `CITE` line for all 36 blocks at its final gate and shipped one citing `func AddWebhook` for a finding about `TestWebhook`, because the body never said to read that line; the fix was a sentence in the final-gate step that names the `CITE` shape and the mismatch to look for.

- **A passing checker prints what it did not check.** A green result ends the model's search, so the sites the checker cannot see go unexamined. The run that measured it: `references/agents/claude-code.md`, "Grading" (read when a skill's checker passes and the work is still incomplete).
- **A WARN the model can argue with is satisfied.** One audit gate printed `WARN two findings cite internal/api/cache.go:18` at its final gate; the run re-read it as correct because the getter is where both cache effects are observed, replied, and shipped. A defect that scores as a miss is a FAIL: the same check now fails the pair, and the two-file WARN that the two-path `Sink:` rule makes normal stays a note.
- **A status word names what the script observed.** A plan checker set a marker on its first PASS and printed `reviewed` on every later one. The body told the model to re-read the plan after a pass, so the 27B edited between two passes, saw `reviewed` with no reviewer called, read the script to find out why (two calls), and called the reviewer anyway; a model that takes the word skips the review. The script can count its own passes and cannot see a tool call. The later PASS now says the call was printed before and prints it again, and the re-read moved ahead of the check: on the next run the reviewer call came 6 seconds after the first PASS with no edit in between.
- **A sweep that leaves no artifact is not a phase.** Step 4 told one run to enumerate routes "again before the final gate"; the only enumeration was a `grep Handle` at minute 0:55, and both of its misses (logout redirect, time-seeded API key) were routes in files the report already proved. The gate now prints `ROUTE <path:line> <route>` for every registration and fails a route named by no ledger row and no report bullet: 8 uncovered routes on that run, one row each. Handler-symbol and parent-path matches keep the count honest (a literal-only check demanded 21).
- **A workaround in a harness is a finding.** A delete PoC failed because the app served a stale cached row after the delete; the model wrote the cause into its thinking, filed it as "already known", and rewrote the assertion to read through an uncached route. The stale cache was a keyed finding that run never reported. When an artifact is changed to route around application behaviour, that behaviour belongs in the ledger first.
- **A hand-filled evidence column gets fabricated or escaped.** A `ran` column for exit codes got 42 exit codes from 6 shell calls, or `ask` on 26 of 29 rows.
- **A negative cell the gate accepts is an escape hatch.** In a coverage table, `clean`, `none` and `n/a` are negative claims; without an executed probe they become the default answer. One audit's state sweep took `L-NNN` or `clean` in its repeat and concurrent cells; the cache lock, pay race and coupon repeat were recorded as `clean` or left without a lead and missed by every run, and the CSV formula had no cell at all. Make the gate reject `clean` without a probe log (command plus observed output), and print the probe each cell still needs. A `no sink` recon row is a negative claim with the same tax.
- **A mandatory per-item tool call is a loop surface.** Moving the exit codes into a script fixed the fabrication and became the loop: every run spent its budget there. A tool that refuses with the same message has the 4B alternating between two attempts for 20 minutes, and softening the refusal to "noted, skipped" only moved the loop to four invented commands. An identical tool answer carries no new information, so the model never leaves. Dropping the script gave 10/11/11, the steadiest triple of the session.
- **Gate the finish on hard failures only.** Under `--strict` an unfixable warning (a runtime path documented in the README but absent from the checkout) kept the scaffolding alive in three of three runs, and one run spent its last ten minutes rewriting files at it. Say in the same output that the remaining warnings are notes for the user and the run stops.
- **Give the checker the oracle the repo already holds.** The path check tested existence on disk alone, so a correctly documented build artifact warned like a typo. The 4B worked out that the warning was wrong, had nowhere to put that, and repeated the same reasoning paragraph a dozen times before building the binary to satisfy the checker. `git check-ignore` in the check ended it. The same class on a plan checker: it failed every cited path missing from the repo, and a 27B that had verified a reviewer's finding in the Go standard library cited `net/http/routing_tree.go`, got `does not exist under <repo>`, and deleted a true citation to pass. The repo's own top-level directories are the oracle: a missing path fails only when its first segment is a directory there.
- **An error is one line naming the next action.** The audit run before the file existed printed `not a file` plus 40 lines of usage. The 4B read the usage as a puzzle and passed the ledger as the target; the audit accepted it, printed "removed, the work is done", and AGENTS.md was never written. "Write it first, then audit it", plus outright refusal of an input that can only be a mistake (the ledger as the file), closed it.
- **Exit 0 proves nothing about existence.** A Makefile `%:` catch-all returns 0 for any target, so running an invented target "verified" it. Check the target against the runner file.
- **A gate named after a later step is skipped when that step is.** A lint worded "MUST exit 0 before anything renders" ran in 0 of 5 runs whose task held the render back: each one handed the lint to the user as the first command of its reply, and one shipped two defects the lint reports. "Run it yourself right after writing the two files; it needs no render server" ran in 2 of 5. Prose raised the rate and left the gate optional; having the later step's script call the lint itself is the structural fix, untested here.

## Scaffolding and environment

- **Delete the scaffolding in the step that proves it is done.** The user was supposed to remove the ledger; nobody did. The clean audit now prints the counts and deletes it. A step the model has to remember is a step the 4B skips.
- **An environment failure can look like a control failure.** `GOCACHE` on a 2 GiB tmpfs, a patched copy per PoC at 4 workers, 137 MB of `vendor` each: three gate rounds reported 9, 18 and 26 failed controls, and every one was ENOSPC. Pin caches into the run dir, and print the failing run's last output line next to the verdict.
- **Share the control build across artifacts.** Audit runs copied the repo and built a patched binary for each PoC's `CONTROL=1` (28 of 30 in one run, 25 of 26 in another), paying a full build per finding and risking ENOSPC. Patch one file through the build's overlay (`go build -overlay`) or one shared patched tree per defect class, and reuse it; the control still re-runs the same attack.
- **A fixture-tuned value breaks when the fixture moves.** A traversal payload sized to the scratch depth returned 404 one directory deeper. Overshoot, and keep the gate's `TMPDIR` where the artifact expects it.
- **Retries do not rescue a narrow race.** 19 edits in 53 minutes on bursts of 40 and 120 against a cap of 4, and the final burst still failed two of five re-runs. Size it at 20x the cap in one shot and stop at five tries.
- **Long runs that work look like this:** incremental report blocks from the first proven item, a notebook carrying the gate's format contract, a gate run seven times mid-run. That run reported zero planted decoys and zero inventions, and the model redacted a secret literal and deleted its own debug scripts without being asked.
